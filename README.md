# RATEIT

RATEIT — соревновательная платформа для **Standoff 2** с рейтингом, подбором матчей, профилями игроков и историей результатов.

Планируемые клиенты:
- Android-приложение.
- Telegram Mini App внутри Telegram-бота.

Оба клиента должны использовать единый аккаунт, API и базу данных.

> **Текущий статус:** ранний этап разработки. Демонстрационный веб-клиент опубликован на Render: https://rateit-wthq.onrender.com/. Первая сборка Render завершилась успешно. Регистрация, постоянное хранение данных, реальные очереди матчмейкинга и интеграция с Telegram пока не реализованы.

## Навигация приложения

Нижняя панель состоит из пяти разделов:
1. **Главная**
2. **Друзья**
3. **Играть** — центральная кнопка запуска подбора.
4. **История матчей**
5. **Профиль**

## Аккаунт и авторизация

Планируемые способы входа:
- Google.
- Telegram.
- Facebook — если интеграцию получится реализовать.

Один пользователь RATEIT должен иметь единый профиль на Android и в Telegram Mini App. Несколько способов входа должны привязываться к одному аккаунту, а не создавать дубликаты.

## Профиль игрока

Профиль должен показывать:
- Ник и Standoff 2 ID.
- Игровые часы.
- Уровень, эмблему и ELO.
- K/D/P — точный состав и формулы показателей ещё предстоит утвердить.
- Количество матчей и процент побед.
- Полосу результатов: победы и поражения.
- Самую успешную и самую неуспешную карту.

Статистика рассчитывается только по матчам, зарегистрированным в RATEIT. Пока интерфейс использует демонстрационные данные.

## Часы и подбор

При регистрации пользователь указывает Standoff 2 ID. Автоматическое получение часов возможно только после проверки доступного и разрешённого источника данных. Пока такой источник не подтверждён, нельзя обещать автоматическую проверку.

Для отображения часы округляются **вниз до ближайших 10**:

`Math.floor(hours / 10) * 10`

Примеры: 178 → `170+`, 187 → `180+`, 193 → `190+`, 205 → `200+`.

Ограничение подбора: разница между часами двух игроков — не более 50 включительно:

`Math.abs(playerA.hours - playerB.hours) <= 50`

Примеры: 100 и 150 подходят; 100 и 151 — нет. Правило сравнения для целой команды ещё предстоит окончательно определить.

## ELO и уровни

Новый игрок начинает с **751 ELO — уровень 3**.

| Уровень | Диапазон ELO |
|---|---:|
| Challenger | Топ-1000 игроков, отдельный статус |
| 10 | 2000+ |
| 9 | 1750–1999 |
| 8 | 1530–1749 |
| 7 | 1350–1529 |
| 6 | 1200–1349 |
| 5 | 1050–1199 |
| 4 | 900–1049 |
| **3** | **751–899** |
| 2 | 501–750 |
| 1 | 100–500 |

Эмблемы должны быть оригинальными для RATEIT и опираться на предоставленные референсы, без копирования чужих защищённых изображений и фирменного оформления.

## Матчмейкинг и матчи

Возможные режимы 5×5 и 2×2 пока предварительные. В план входят:
- Подбор игроков и формирование команд.
- Рейтинг ELO и уровни.
- Пати с друзьями.
- Подтверждение готовности участников.
- История матчей и статистика карт.
- Лидерборды и сезоны.
- Турниры и уведомления.
- Проверка результатов и разбор спорных матчей.

### Создание игровых комнат

Telegram-бот сам по себе не управляет Standoff 2. Полная автоматизация потребует подтверждённого официального API или другого разрешённого способа интеграции. Наличие такой возможности пока не подтверждено.

Для первой версии предусмотрен полуавтоматический сценарий: RATEIT подбирает игроков и формирует команды, капитан вручную создаёт игровую комнату, участники подтверждают готовность, а результат фиксируется в RATEIT.

## Технологическая структура

- `apps/web` — React, TypeScript и Vite; веб-интерфейс и основа будущего Telegram Mini App.
- `apps/api` — сервер API на Fastify.
- `packages/shared` — общие константы и правила RATEIT.
- `apps/api/db/schema.sql` — начальная SQL-схема PostgreSQL.
- `apps/api/.env.example` — пример переменных окружения без секретов.

## API, добавленные на текущем этапе

| Метод и путь | Назначение |
|---|---|
| `GET /health` | Проверка состояния API |
| `GET /api/v1` | Информация о сервисе |
| `GET /api/v1/config` | Стартовый ELO, уровни и ограничение часов |
| `GET /api/v1/hours/prefix?hours=187` | Префикс часов, например `180+` |
| `GET /api/v1/matchmaking/hours-check?a=100&b=150` | Проверка разницы часов |
| `GET /api/v1/elo/rank?elo=751` | Уровень, следующий порог ELO и прогресс |

Для некорректных значений API возвращает ошибку HTTP 400. Маршрут ранга рассчитывает обычный уровень по ELO; статус Challenger должен определяться отдельно по позиции игрока в рейтинговой таблице.

### Примеры

`GET /api/v1/elo/rank?elo=751`

Вернёт уровень 3 и порог следующего уровня — 900 ELO.

`GET /api/v1/matchmaking/hours-check?a=100&b=151`

Вернёт `compatible: false`, так как разница составляет 51 час.

## Анализ CF Ranking

Сайт для изучения: https://cfranking.tech/

По открытым материалам CF Ranking описывает соревновательный формат Standoff 2 с подбором 5×5, рейтингом ELO, пати, выбором/баном карт, историей матчей, сезонными таблицами, подтверждением готовности и проверкой результата.

Для RATEIT стоит самостоятельно оценить следующие идеи:
- Группы друзей и совместный поиск матча.
- Таймер подтверждения готовности.
- Голосование или последовательный бан карт.
- Карточка лобби с составами команд и данными для ручного входа.
- Загрузка подтверждения результата и разбор спорных случаев.
- Сезонные таблицы лидеров.

Не копируем чужой код, тексты, изображения, логотипы, фирменный стиль или точную компоновку. Не переносим чужие правила ELO и рейтинговые диапазоны: RATEIT сохраняет собственный старт 751 ELO и таблицу уровней.

## Важные оговорки

Наличие файлов и маршрутов не означает, что весь сервис готов к использованию. API пока не подключён к постоянной базе данных; демо-профиль и история не являются реальными пользовательскими данными. Перед публичным запуском нужны сборка, тесты, настройка авторизации, защита API и проверка интеграций.
